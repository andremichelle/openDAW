## Summary
The reporter wants to:
1. Drag an effect out of a composite layer to the parent chain: hold it over the composite device (or back control) for one second and the panel switches to the parent chain.
2. Drag a new effect from the browser over a layer row in the composite: dropping within one second appends it to that layer without entering it. Holding for one second enters the layer, so it can be dropped at any position in the layer's chain. After entering, wait another second before the panel may switch back, to avoid flipping.

## Current state
1. Done: dropping a new effect onto a branch row appends it to that branch, onto a row edge creates a new branch (`packages/app/studio/src/ui/devices/AudioCompositeEntryDnD.ts:77`). Dropping an existing effect from the parent chain onto a branch moves or copies it into that branch (`:89`, commit `16936d5bf`). The instrument composite has the same for layers (`packages/app/studio/src/ui/devices/InstrumentCompositeLayerDnD.ts:71`).
2. Done: a cross chain move into the chain shown in the device panel (`packages/app/studio/src/ui/devices/DevicePanelDragAndDrop.ts:198`).
3. Removed: dropping an effect on the "back" pill to move it to the parent chain was added in `8332059d6` and removed again in `5aa1149f1`. Today the back button in a cell editor is click only (`packages/app/studio/src/ui/devices/CompositeCellEditor.tsx:92`).
4. Done for tracks (#403, `23494659a`): holding a device drag over a track header for one second switches the device panel to that unit (`packages/app/studio/src/ui/timeline/tracks/audio-unit/headers/HoverEditSwitch.ts:20`, delay 1000 ms at `:7`).
5. Missing: hover to enter a layer, hover to leave a layer, and inserting at a position inside a branch from the composite row (always appends).

## Analysis
1. `createHoverEditSwitch` already implements the timing (delay, dragover gap, sealed history entry). It is bound to an `AudioUnitBoxAdapter` and calls `audioUnit.edit(box.editing)`. Generalizing it to take any editing target vertex makes it usable for composite cells (enter) and for the cell editor's back target (`MenuItems.backTargetOfCell`, `packages/app/studio/src/ui/devices/menu-items.ts:120`).
2. Switching the panel rebuilds the device editors while the drag source may vanish. `DragAndDrop` already ends drags on document level for that case (`packages/app/studio/src/ui/DragAndDrop.ts:18`).
3. The reporter's "wait another second before going back" is covered if the hover switch only arms after the pointer has entered the target fresh (the existing `isEditing` check at `HoverEditSwitch.ts:28` already avoids re-entering the current chain).
4. The drop on a row within the delay should keep appending, which is today's behaviour.

## Possible solution
1. Generalize `createHoverEditSwitch` to accept a `Vertex` editing target and move it to a shared place.
2. In `AudioCompositeEntryDnD.installTarget` and `InstrumentCompositeLayerDnD.installTarget`, feed `hover()` on dragover for device drags and `cancel()` on leave and drop, with the cell box as target.
3. Make the cell editor's back button a drop target that hovers to the parent chain, and optionally accepts a direct drop that moves the effect to the end of the parent chain (restoring `8332059d6` behaviour).
4. Keep the appending drop on rows as it is.
