## Summary
The reporter wants control over the value resolution of automation regions:
1. Divide the value range into N equal steps.
2. A boolean mode that only allows minimum and maximum.
3. Show and enter values in the native unit, for example MIDI CC 0 to 127, instead of guessing percentages.
4. Switch between native and percent display when the native unit is known.

The attached screenshot (downloaded, `images/0038/img1.png`) shows a MIDIOutput device sending to a Roland Digital Piano with two CC parameters, Sustain Pedal (#64) at 99.9 % and Soft Pedal (#65) at 0.0 %. The reporter wants these as on/off.

## Current state
1. A MIDI Output CC parameter is a float32 unipolar field shown in percent: `packages/studio/forge-boxes/src/schema/devices/instruments/MIDIOutputParameterBox.ts:13`. The adapter creates it with `ValueMapping.unipolar()` and `StringMapping.percent({fractionDigits: 1})`: `packages/studio/adapters/src/devices/instruments/MIDIOutputDeviceBoxAdapter.ts:65`.
2. The engine rounds the unit value to 0..127 when sending: `crates/engine/src/midi_output.rs:425`.
3. The value editor already quantizes through the parameter's value mapping (`mapping.x(mapping.y(value))`): `packages/app/studio/src/ui/timeline/editors/value/ParameterValueEditing.ts:92`. Non floating mappings already create events with `Interpolation.None`: `packages/app/studio/src/ui/timeline/editors/value/ValueEditor.tsx:147`. Moving events is quantized too: `packages/app/studio/src/ui/timeline/editors/value/ValueMoveModifier.ts:125`.
4. The paint tool does not quantize and always writes linear events: `packages/app/studio/src/ui/timeline/editors/value/ValuePaintModifier.ts:120` and `:156`.
5. An older analysis (`plans/issues/038-automation-region-unit-resolution.md`) proposes a persisted per region setting on `ValueRegionBox`/`ValueClipBox`. No commits address this issue.

## Analysis
1. The editor is already driven by the parameter's `ValueMapping` and `StringMapping`. Stock device parameters with stepped mappings (`ValueMapping.values`, `linearInteger`, `bool`, `packages/lib/std/src/value-mapping.ts:150`) already get stepped automation. The missing piece is that MIDI Output parameters always use a continuous percent mapping.
2. The field is float32, so `linearInteger(0, 127)` cannot be used directly with `createParameter` (the mapping type must match the field type, `packages/studio/adapters/src/ParameterAdapterSet.ts:35`). A float mapping that snaps to N steps (non floating) is needed.
3. A generic per region resolution (independent of the parameter) would conflict with the parameter's own mapping and is harder to define for stock parameters. Putting the resolution on the MIDI Output parameter covers the reported case cleanly.
4. The paint tool bypassing `quantize` is a gap that would make any stepped mode leaky.

## Possible solution
1. Add a new field to `MIDIOutputParameterBox`, for example `5: int32 "resolution"` with values 0 (continuous percent), 2 (on/off), 128 (CC 0..127), or a free step count. Use a new field key, never reuse one.
2. Add a stepped float mapping to lib-std, for example `ValueMapping.steps(count)` that returns `round(x * (count - 1)) / (count - 1)` with `floating() = false`.
3. In `MIDIOutputDeviceBoxAdapter` pick mapping and string mapping from the resolution: percent, `On`/`Off`, or integer 0..127. Recreate the parameter adapter when the resolution changes (remove and add in `ParameterAdapterSet`).
4. Add a resolution dropdown per parameter row in `packages/app/studio/src/ui/devices/instruments/MIDIOutputEditor/ControlValue.tsx`.
5. Make `ValuePaintModifier` use `context.quantize` and `Interpolation.None` for non floating mappings, matching `ValueEditor.tsx:144`.
6. Tests: value editor quantization for a stepped mapping, adapter mapping switch, engine CC output for 0/1 values.

## Complexity
medium. Box schema (forge-boxes, boxes regeneration), lib-std mapping, adapters, MIDI Output editor UI, value editor paint tool. No engine change, the engine already rounds to 0..127.

## Open questions
1. Should the resolution live only on MIDI Output parameters, or also as a general per automation region override?
2. Which presets for the dropdown: continuous, on/off, 0..127, and a free step count?
