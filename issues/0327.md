## Summary
Individual tracks in a project keep disappearing for the reporter and his girlfriend. He suspects he hits Delete twice while deleting a take he does not like, and notices hours later. Undo is not reliable for finding them. He asks for a panel listing deleted tracks, grouped by origin, where he can listen to and restore them, like a recycle bin. The screenshot (viewed) shows a timeline with several audio units, each with many "Audio" sub tracks holding "Take 1" regions, on a small screen where only a few tracks are visible. He mentions a dialog asking whether to delete completely or keep in local storage, which was the old "Keep Sample?" dialog.

## Current state
1. The "Keep Sample?" dialog is gone. Samples leaving a project are marked as garbage and deleted at the next studio start unless a saved project, template or preset still uses them (`packages/studio/core/src/samples/SampleGarbage.ts:47`, called at `packages/app/studio/src/boot.ts:193`, commit `0bca570d8`).
2. A focused track header deletes its track on the Delete or Backspace key: content track at `packages/app/studio/src/ui/timeline/tracks/audio-unit/headers/AudioUnitTrackHeader.tsx:132`, whole audio unit at `packages/app/studio/src/ui/timeline/tracks/audio-unit/UnitLane.tsx:154`. Headers are focusable (`tabindex={-1}`, `AudioUnitTrackHeader.tsx:62`) and a pointerdown on the header focuses the track.
3. Undo history is in memory only (`packages/lib/box/src/editing.ts:73`) and a new edit after undo drops the redo branch (`editing.ts:366`).
4. No trash or deleted tracks list exists.

## Analysis
Likely cause of the vanishing tracks: after clicking a track header (to select or focus it), pressing Delete to remove a region deletes the track instead, with no confirmation and no visible feedback when the track is off screen. With a small screen this goes unnoticed. Since the sample is only marked as garbage, it still exists until the next start, but there is no UI to bring it back.

## Possible solution
1. Reduce accidental deletion: when a track holds regions, either ask for confirmation on keyboard delete of a track, or show a short notification "Track deleted, Undo" with an undo action.
2. Recycle bin (if wanted): on track deletion, keep a serialized copy of the deleted track subgraph (track box, regions, events, referenced file boxes) in a project local list. A panel lists them with name, origin unit and time, a preview player and Restore, which re inserts the subgraph through the existing transfer code. SampleGarbage must treat samples referenced by the bin as in use.
3. Store the bin with the project or in session memory only, to be decided.

## Complexity
medium for the bin (core transfer reuse, a new panel, SampleGarbage interaction). Item 1 alone is small (two key handlers plus a notification).

## Open questions
1. Recycle bin panel, or only a safer delete (confirmation or undo toast)?
2. Should the bin survive saving and reloading the project?
