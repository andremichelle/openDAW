## Summary
An analyser with oscilloscope, spectrum analyser, spectrogram, stereo phase scope, pitch detector and loudness measurement. Comments:

1. kaiartikkas wants to compare multiple tracks, for example the track itself and a second track via a sidechain style input, to shape one sound against another with an EQ. Two tracks would be enough.
2. André thinks comparison is more of a view where you switch tracks, and says more than one track can be pulled in, the question is how the UI handles it.
3. BeatMaxPrediction wants at least two input sources shown as layers, and precise axis labels (dB, percent).

## Current state
1. A Mixer Analysis panel exists (Delivery A of `plans/analyser-plugin.md`, commits e547b3ee6, c14fa6e76, f2456d33a). Cards: Spectrum, Spectrogram, Level with LUFS M/S/I, Scope, Gonio, VU meters (`packages/app/studio/src/ui/analysis/`).
2. It analyses the master only. The cards subscribe to fixed engine addresses on `UUID.Lowest` (`packages/studio/adapters/src/EngineAddresses.ts:6` to `:10`, used in `packages/app/studio/src/ui/analysis/SpectrumCard.tsx:110` and `LevelCard.tsx:108`). The per-unit source selection of the plan is not built, per-unit strips only broadcast a peak meter (`crates/engine/src/audio_unit/wiring.rs:53`).
3. Delivery B, the insert device, is not built (`plans/analyser-plugin.md:131`).
4. No pitch detector card. A pitch detector exists in Autotune's core (`crates/stock-devices/device-autotune/src/lib.rs:2`, tuner broadcast at `:37`), which could be reused.
5. No multi-source comparison.

## Analysis
1. Remaining features: source selection per unit (plan Delivery A), pitch detector card, the insert device (Delivery B), and comparison of two or more sources.
2. Comparison fits the panel better than the device: the panel can subscribe to the broadcasts of several units at once and draw them as layers. As a device, a second source would need a sidechain style pointer (like the Compressor's) and a second analyser in the device crate.
3. Each analysis channel must stay gated by `broadcast_active` so hidden cards cost nothing, as the plan says.

## Possible solution
1. Engine: let the audio unit strip broadcast spectrum, loudness, scope and gonio under the unit uuid plus a sub-address, gated per subscription (`crates/engine/src/audio_unit/wiring.rs`, strip in `engine-env`).
2. Panel: a source selector (selected unit, pinned unit, master) in `AnalysisPanel.tsx`, the cards read the address from the source.
3. Comparison: a second source selector on the Spectrum card that draws a second curve in another colour. Later the same for other cards where it makes sense.
4. Pitch card: reuse the Autotune detector as a shared DSP module, broadcast detected note and cents.
5. Delivery B: `AnalyserDeviceBox` passthrough device crate that reuses the same DSP and card renderers, with an optional sidechain input for comparison.
6. Check axis labels on every card (dB, Hz, LUFS) against the request.

## Complexity
large. Engine broadcast channels per unit (`crates/engine`, `crates/engine-env`), panel UI in `packages/app/studio/src/ui/analysis`, a new DSP card, and for Delivery B a new box, adapter, device crate and editor.

## Open questions

2. Should the insert device (Delivery B) still be built once the panel supports any unit as source?
