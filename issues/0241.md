## Summary
Even very short notes on the Soundfont instrument cause long sustains that muddy the mix. The reporter asks for an envelope on the Soundfont player.

## Current state
1. The Soundfont device has no parameters (`crates/stock-devices/device-soundfont/src/lib.rs:8-9`). The box only has `file` and `preset-index` (`packages/studio/forge-boxes/src/schema/devices/instruments/SoundfontDeviceBox.ts:5-8`).
2. Each voice uses the envelope from the SF2 file. The envelope is linear in amplitude for attack, decay and release (`crates/stock-devices/device-soundfont/src/voice.rs:26-118`), set per voice at `voice.rs:203`.
3. The TS side converts the SF2 generators to seconds and levels (`packages/studio/core-wasm/src/soundfont-simplify.ts:155-163`):
   1. Instrument values override preset values (`soundfont-simplify.ts:120-121`).
   2. Sustain is `1 - x / 1000` (`soundfont-simplify.ts:162`).
   3. Loop modes 1 and 3 both become "loop forever" (`soundfont-simplify.ts:158`).

## Analysis
The long tails are most likely caused by three deviations from the SF2 2.04 spec, not only by a missing user envelope:
1. Release and decay: SF2 defines the volume envelope decay and release as linear in dB, the time being the time to fall by 100 dB. The device ramps linearly in amplitude instead (`voice.rs:112-118`). With a 2 s release the spec is at about -20 dB after 0.4 s, the linear ramp is still at -1.9 dB. Releases sound several times longer than intended.
2. Sustain: `sustainVolEnv` is an attenuation in centibels, so the level is `10^(-x / 200)`. `1 - x / 1000` makes 100 cB (-10 dB) a level of 0.9 (-0.9 dB), so sustain is far too loud.
3. Preset generators are additive offsets to the instrument values in SF2, not fallbacks. A preset that shortens the release has no effect today.
4. Loop mode 3 (loop while held, then play to the sample end) loops forever after note off, which keeps looped samples ringing for the full release.
On top of that, a user envelope (attack, decay, sustain, release offsets or scales) is a reasonable feature.

## Possible solution
1. Fix the conversion in `soundfont-simplify.ts`: sustain as `10^(-cB / 200)`, preset generators added to instrument generators (timecents add, then convert).
2. Change the `Adsr` in `voice.rs` to a dB linear (exponential in amplitude) decay and release, keeping the attack linear as the spec says.
3. Pass loop mode 3 through the blob and stop looping on release in `voice.rs`.
4. Add a golden test against a known renderer (for example FluidSynth output for one preset) to pin the envelope.
5. Feature: add `attack`, `decay`, `sustain`, `release` parameters to `SoundfontDeviceBox` as multipliers or offsets on the file's envelope, read in the device via `parameter_changed`, plus editor knobs.

## Complexity
medium. Steps 1 to 4 touch `packages/studio/core-wasm/src/soundfont-simplify.ts`, `crates/stock-devices/device-soundfont/src/voice.rs` and the blob layout in `blob.rs` (WASM contract, both sides in lockstep). Step 5 adds schema fields, adapter parameters and editor controls. Steps 1 to 4 change the sound of existing projects that use soundfonts.

## Open questions
1. Is changing the sound of existing projects acceptable for the spec fixes, given that they move toward the SF2 standard?
2. For the user envelope: offsets in seconds, or multipliers of the file's own values?
