## Summary
With a one-channel monitoring source (forced mono, or a mapping that uses one side only), the effects-monitoring return was the channel strip's left output on both sides. Panned hard right it was silent, a stereo effect was heard as its left half.

## Analysis
`MonitoringRouter` gave a mono source one worklet channel, the engine (`copy_monitor_outputs`) copies the strip's right buffer only when the entry has a right channel, and the router sent the one return channel to both sides.

## Fix
Every source takes two channels in `MonitoringRouter`, a mono input is fed into both, so the strip's stereo output comes back. The wire format is unchanged. To keep the old capacity (eight mono sources), the monitoring channels go from 8 to 16 (engine `MONITOR_CHANNELS`, processor staging, the worklet's second output, `MAX_MONITORING_CHANNELS`): eight sources of any kind now, before eight mono or four stereo. The router also no longer leaks a splitter per rebuild. Tests: `packages/studio/core/src/MonitoringRouter.test.ts`, `packages/studio/core-wasm/test/effects-monitoring-mono-pan.test.ts` (a mono pair on channels 14 and 15, strip hard right).
