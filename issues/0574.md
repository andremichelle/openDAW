## Summary
`RuntimeNotifier.approve` resolves `true` when no notifier is installed. `UnstoredRecording.offerDownload` loops on it, so for an SDK app without a notifier every refused save requests the picker again. The studio installs a notifier and is not affected.

## Analysis
Siblings with the same unbounded retry: `Promises.approvedRetry` (`packages/lib/runtime/src/promises.ts`, used by the seven cloud backup uploads) and the retry loop in `CloudBackup.backup`. `network.ts` is already bounded. Changing the default of `approve` to false would change about 20 call sites for SDK users (`Files.save` would never save).

## Fix
1. Additive `RuntimeNotifier.installed` (`RuntimeNotification.Status`), not part of the `Notifier` or `Installer` interfaces, so implementers are not broken.
2. `offerDownload`, `approvedRetry` and `CloudBackup.backup` make one attempt and give up (rethrow or return false) when no notifier is installed.
3. SDK readme: a Notifications section on installing a notifier.
Tests: `UnstoredRecordingWithoutNotifier.test.ts`, `packages/lib/runtime/src/promises.test.ts`.

## Progress
1. Fixed on next-release, uncommitted.
2. Not testable in the studio (it installs a notifier), covered by the unit tests.
