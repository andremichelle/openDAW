## Summary
Recording a hardware synth needs two tracks today: a MIDI Output track for the notes and an audio track for the synth's sound. The reporter asks for a "Record Hardware" option on the MIDI Output device with an input selection dialog. While recording, the incoming audio is written to an audio sub track of the same unit. The attached image shows such an "Audio" sub track under the unit in the track list. Input monitoring should be available in the device or in its menu, like on audio tracks. This is the same idea as an "External Instrument" device in other DAWs.

## Current state
1. An audio unit has one `capture` pointer (`packages/studio/forge-boxes/src/schema/std/AudioUnitBox.ts:58`). `CaptureDevices` creates exactly one capture per unit, MIDI or audio (`packages/studio/core/src/capture/CaptureDevices.ts:25`). A MIDI Output unit gets a `CaptureMidi`.
2. `RecordAudio` already finds or creates an audio track on the capture's unit (`packages/studio/core/src/capture/RecordAudio.ts:76`), so recording into any unit's audio track works once a `CaptureAudio` exists for it.
3. Engine: the MIDI Output node is silent and feeds the unit's audio effects and strip (`crates/engine/src/audio_unit/mod.rs:185`). Its wiring already inserts the monitor mix for monitored input (`crates/engine/src/audio_unit/wiring.rs:432`), so effects monitoring of a mapped input would reach the MIDI Output chain.
4. Audio regions are only played for Tape units: the engine dispatches by instrument box type (`crates/engine/src/audio_unit/wiring.rs:215`, `:217`). Audio tracks on a MIDI Output unit would stay silent.
5. No commits reference the issue.

## Analysis
1. Two captures per unit are needed (MIDI for notes, audio for the return). The `capture` field holds one pointer, so either a second pointer field or a capture box that holds both is required. A new field key is additive.
2. Playback needs the MIDI Output wiring to also run the audio region player over the unit's audio tracks and sum it into its silent output, like `reconcile_tape` does.
3. Arming and the record session must handle one unit with two captures: arm both together, write notes and audio as one take, and apply input latency compensation to the audio.
4. Hardware round trip latency (MIDI out to audio in) is longer than plain input latency. The MIDI Output `delay` setting and the audio input latency must be combined so the recorded audio lines up with the notes.

## Possible solution
1. Schema: add an optional `audio-capture` pointer to `AudioUnitBox` (new key), accepting `CaptureAudioBox`. Only offered for MIDI Output units.
2. `CaptureDevices`: create a `CaptureAudio` for that pointer in addition to the main capture. The record session arms and records both.
3. UI: a "Record Hardware Audio" option in the MIDI Output device menu, with the existing audio input selection and monitoring modes from the Tape track menu.
4. Engine: in `reconcile_midi_out`, add the audio region player reading the unit's audio tracks before the audio effects, sharing the code with `reconcile_tape`.
5. Tests: a MIDI Output unit with an audio region renders the region, monitoring reaches the chain, and a recording writes both a note region and an audio region.

## Complexity
large. Box schema (`packages/studio/forge-boxes`), capture and recording (`packages/studio/core/src/capture`), MIDI Output device UI (`packages/app/studio`), engine wiring (`crates/engine/src/audio_unit/wiring.rs`), tests in both layers.
