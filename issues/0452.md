## Summary
The reporter (who considers implementing it) proposes integrating Kyutai's MuScriptor multi instrument audio to MIDI model as a client side transcription feature, like the existing stem splitter. Community ONNX exports exist (for example cursedhelm/cubaser-muscriptor-medium-onnx with `conditioner.onnx` and an autoregressive `model.onnx`). The small model has about 103M parameters (about 200 MB FP16, about 105 MB Q8). Pipeline: chunk audio into 5 s windows and compute a 512 bin mel spectrogram in JS, run ORT Web with WebGPU, write the autoregressive decoding loop with KV caches until EOS, port the tokenizer to map tokens to note events, stitch chunks (tie prologue) and insert notes into the note editor.

## Current state
1. `packages/lib/inference` already wraps ONNX Runtime Web (`onnxruntime-web` in `packages/lib/inference/package.json:27`) with a worker, model download into OPFS with SHA-256 check (`packages/lib/inference/src/ModelStore.ts`), execution provider choice (WebGPU, WASM) and a task registry (`packages/lib/inference/src/registry.ts:4-9`).
2. The stem splitter uses it (`packages/app/studio/src/service/NeuralDemux.tsx`, tasks `stem-separation` and `stem-separation-alt`).
3. An `audio-to-midi` task is registered with the Basic Pitch model (230 KB, Apache-2.0, self hosted on assets.opendaw.studio), but `run` panics with "not implemented yet": the note tracking post processing is missing (`packages/lib/inference/src/tasks/BasicPitchTask.ts:22-41`). There is no UI for it.
4. A task holds exactly one model file (`ModelStore.ts:20`, `MODEL_FILE = "model.onnx"`). MuScriptor needs two (conditioner plus decoder).

## Analysis
1. The infrastructure the issue asks for exists. The open work is model specific: mel front end, autoregressive decoding with KV cache in ORT Web, tokenizer, chunk stitching.
2. Basic Pitch is already wired, tiny and fast, but polyphonic single instrument (piano range, no instrument labels). Finishing its post processing gives a working audio to MIDI feature first, with far less risk.
3. MuScriptor adds multi instrument output, at a 100 to 200 MB download and an autoregressive loop that is slow in WebGPU (many sequential decoder steps per 5 s chunk). Memory and speed on average laptops need measuring.
4. Licensing of the MuScriptor weights and of the community ONNX export must allow redistribution if openDAW self hosts them, as it does for the other models.

## Possible solution
1. Implement `BasicPitchTask.run`: resample to 22050 Hz mono, run the model in windows, then the published onset and note tracking (peak picking, minimum note length, pitch bend average) to produce `BasicPitchNote`s.
2. UI: "Convert to MIDI" on an audio region or sample that creates a note region on a new instrument unit at the same position (tempo map aware).
3. For MuScriptor: extend `TaskDefinition` and `ModelStore` to multiple model files per task, add a `audio-to-midi-multi` task with the mel front end, decoding loop and tokenizer in the inference worker, and map instrument tokens to separate note tracks.
4. Tests: golden note lists for short fixtures in `packages/lib/inference`.

## Complexity
large. Basic Pitch alone is medium (`packages/lib/inference` task plus a UI action in `packages/app/studio`). MuScriptor adds multi file model support in `ModelStore` and `Task`, a mel spectrogram, an autoregressive decoder and a tokenizer port.
