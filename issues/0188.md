## Summary
The reporter asks for an audio effect that shifts the pitch of live audio in real time. Proposed parameters: Pitch (semitones, possibly more than one octave), Fine (-100 to +100 cents), Mix, Mode (Live low latency / HQ), Output (-12 to +12 dB). Techniques listed: dual read head delay ("Jungle"), WSOLA, phase vocoder, PSOLA, with candidate libraries (SoundTouchJS, Kali, phaze, vexwarp, soundstretch-web, rubberband-wasm, several of them LGPL or GPL). Visual ideas: tape speed, turntable strobe dots, pitch fader. Robin Schmidt offered his granular plus grain adaptive (PSOLA like) pitch shifter from RS-MET for adaptation. kaiartikkas built a Werkstatt script with the dual playhead method, tried a phase vocoder and found it not suitable.

## Current state
1. There is no dedicated audio pitch shifter in `EffectFactories.AudioNamed` (`packages/studio/core/src/EffectFactories.ts:688-709`). `Pitch` is a MIDI effect that transposes notes (`crates/stock-devices/device-pitch/src/lib.rs:1-6`).
2. The Autotune audio effect already has a manual `shift` parameter of -12 to +12 semitones (`packages/studio/adapters/src/devices/audio-effects/AutotuneDeviceBoxAdapter.ts:78-80`). It drives a streaming TD-PSOLA shifter (`crates/dsp/src/psola.rs:1-22`), ratio clamped to 0.5..2.0 (`psola.rs:18-19`). With amount 0 it acts as a pitch shifter, but only for monophonic input, because PSOLA needs the detected period (`crates/dsp/src/autotune.rs:1-7`).
3. A Rust port of Signalsmith Stretch is in the repo and used by the engine for time stretching (`crates/signalsmith/src/stretch.rs`). It has `set_transpose_semitones` (`stretch.rs:146`), a streaming path in 128 frame blocks (`stretch.rs:350`) and a fixed latency of half a block (`stretch.rs:340`). It works on polyphonic material.
4. A user made dual playhead shifter exists as a Werkstatt script (not in the repo).

## Analysis
Two engines already exist in the codebase, which covers both requested modes without new third party code or license issues:
1. Live mode: a dual read head delay line shifter (two crossfaded taps sweeping through a short delay). Low latency (a few ms), works on any input, artefacts are a slight chorus. Not yet in `crates/dsp`, but small. Robin Schmidt's design is the same family and could be ported.
2. HQ mode: Signalsmith Stretch with time factor 1 and a transpose. Higher latency (half its block), polyphonic, good quality. Needs latency reporting so the engine's delay compensation keeps the track aligned.
The LGPL and GPL libraries in the issue are not needed.

## Possible solution
1. New box `PitchShifterDeviceBox` (audio effect) with `semitones` (-24..24), `cents` (-100..100), `mode` (Live, HQ), `mix`, `output`.
2. New crate `device-pitch-shifter` in `crates/stock-devices`: Live mode as a dual tap delay shifter in `crates/dsp`, HQ mode via `signalsmith` streaming with transpose. Report the mode's latency to the engine.
3. Adapter, editor (a turntable style pitch fader per the visual ideas), menu entry, manual page, scripting entry.
4. Native tests: frequency of a sine after a shift, latency per mode, no clicks on parameter moves.

## Complexity
medium. New box schema, one new stock device crate (reusing `dsp` and `signalsmith`), adapter, editor, manual. Latency reporting for HQ mode must work with the existing delay compensation.

## Open questions
1. Is the Autotune `shift` enough for monophonic sources, so the new device only needs to cover polyphonic material?
2. Should both modes ship at once, or Live first?
3. Accept Robin Schmidt's offer and port the grain adaptive variant as the Live mode?
