## Summary
André wants to play a MIDI keyboard with a sustain pedal in openDAW. Proposed: find a way to attach the pedal to a parameter.

## Current state
1. Nothing implemented in the studio. `CaptureMidi` forwards note-on and note-off only, CC64 is dropped (`packages/studio/core/src/capture/CaptureMidi.ts:268` to `:279`).
2. Live notes are raw notes with infinite duration ended by their note-off in the Rust sequencer (`crates/engine-env/src/note_sequencer.rs:152` to `:163`).
3. A detailed plan exists: `plans/midi-sustain.md` (aac56fc6b, 8f3307f73, 7631277f8, 47fe00700). Options A to F, recommendation F: a sustain lane per instrument track like the tempo track, carried by region edits, with targets Hold (sequencer holds note-offs), Parameter and Forward (CC64 to WebCLAP and soundfonts). Includes a per device sustain polarity setting (Auto, As is, Inverted) for inverted pedals.
4. A diagnostic MIDI test page is live: `packages/app/studio/public/midi-test.html` (`/midi-test.html`), showing sustain, pitch bend, mod wheel, aftertouch and the polarity modes.

## Analysis
1. Mapping CC64 to a parameter via MIDI learn is not enough: no stock instrument has a sustain parameter, and MIDI learn is a main-thread box edit coalesced per frame while notes are engine signals, so pedal and key events can arrive out of order (plan option B).
2. Holding note-offs in the note sequencer on the same ordered path as live note signals avoids the race and works for every instrument (plan options C and F).
3. Storing the pedal as a lane per track keeps it editable after recording. Region edits must carry the lane.
4. Edge cases listed in the plan: restrike of a held pitch, several capture devices per track, stop and locate releasing held notes, live rooms, offline render parity, half pedal, inverted pedals.

## Possible solution
Following the plan's order for F:

1. Polarity setting and CC64 capture in `CaptureMidi`, a sustain signal next to the note signals, sequencer Hold for live notes only.
2. The sustain lane (new optional field on the audio unit pointing to a `ValueEventCollectionBox`), recording into it, playback Hold in `note_sequencer.rs`.
3. Region edits move, copy and delete pedal events in their range.
4. Parameter and Forward targets.
5. Tests: sequencer hold and release, restrike, stop releases, offline parity, schema round trip with old projects unchanged.

## Complexity
large. `packages/studio/core` capture and recording, engine sequencer and a new signal in `crates/engine-env` and `crates/engine`, schema field and adapter, timeline lane editor, region edit commands, preferences for polarity.

## Open questions
1. Is option F (sustain lane with Hold, Parameter and Forward targets) the agreed direction, or should step 1 (live Hold with polarity) ship first on its own?
2. From the plan: does a parameter change reach voices already in release in every stock instrument (decides whether the Parameter target is useful for release time)?
3. One target per track or several, and where the lane is shown (under the track like tempo, or in the track's automation list)?
