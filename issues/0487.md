## Summary
Werkstatt, Apparat and Spielwerk can only keep state inside the project (`@param`, `@collection`, `@buffer`). The issue proposes a per script storage outside the project so a script can build its own library (patterns, drawn waveforms, wavetables, snapshots) and reuse it in every project. Proposal: an async view side API (`list`, `readText`, `writeText`, `readBytes`, `writeBytes`, `delete`), the processor never touches storage, loading into the device is an undoable transaction, no per script quota, save and load the whole library as a file, validated keys, writes through the OPFS worker. Requirements: a host assigned secure namespace id that the script cannot choose, and garbage collection of orphaned storage. André linked the plan `plans/script-storage.md` in a comment.

## Analysis
1. Keeping storage on the view side avoids async I/O on the audio thread and keeps offline render untouched. Data reaches the processor through existing `@collection` and `@buffer`, so undo works through normal transactions.
2. The id travels in projects, presets and live rooms. Without the seal, a crafted project could reuse an id and access another user's library. The seal binds id plus code hash to a machine secret.
3. Automatic garbage collection is unsafe because projects can live outside OPFS (exports, bundles, cloud). The plan shows unused libraries on the storage page and leaves deletion to the user.
4. Adding fields to the device boxes needs new field keys and must leave existing scripts bit identical (opt in only).

## Possible solution
Follow the phases of `plans/script-storage.md`:
1. `ScriptDataStorage` in `packages/studio/core/src/scripts/` with key validation and `FakeFiles` tests.
2. Schema fields `storage-id` and `storage-seal` on Werkstatt, Apparat and Spielwerk device boxes, `@storage` declaration parsing, id assignment, `ScriptMeta.storage`.
3. Secret, seal, verify, "Allow Library Access" menu entry.
4. `host.storage` in the view runtime over the view `MessagePort`, cross device `subscribe`, Monaco types, a Spielwerk pattern browser example.
5. Save and load library as `.odlib`.
6. Storage page section and the delete dialog for library scripts.
7. Manual, scripting docs, AI starter prompts.
