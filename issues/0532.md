## Summary
The reporter wants Autotune to correct to a hand picked set of notes (for example four notes) instead of one of the eight preset scales, without changing the project key. Proposed: a "Custom" entry in the Scale menu with a 12 note grid like the one in the note editor. André pointed to the new project key that Autotune can follow. The reporter answered that this does not solve it, because the project key should stay unchanged, and noted that the key feature is already in production.

## Current state
1. `AutotuneDeviceBox` has `key` (0..11), `scale` (0..7), `amount`, `retune`, `shift`, `smooth` and `follow` (`packages/studio/forge-boxes/src/schema/devices/audio-effects/AutotuneDeviceBox.ts:7` to `:31`). Follow was added in f664d793e.
2. The adapter maps scale to eight names (`packages/studio/adapters/src/devices/audio-effects/AutotuneDeviceBoxAdapter.ts:61` to `:65`). The editor shows key and scale as knobs (`packages/app/studio/src/ui/devices/audio-effects/AutotuneDeviceEditor.tsx:44`).
3. The DSP already works on an arbitrary 12 bit mask relative to the key: `set_mask` (`crates/dsp/src/autotune.rs:144`), membership test at `:310`. Presets are `SCALE_MASKS` (`:80`). Follow mode already passes the project key's mask through `set_mask` (`crates/stock-devices/device-autotune/src/lib.rs:65` to `:70`).
4. A 12 note toggle grid exists in the note editor: `packages/app/studio/src/ui/timeline/editors/notes/pitch/ScaleConfigurator.tsx:14`. Scale Matrix stores a similar per device array (`packages/studio/forge-boxes/src/schema/devices/midi-effects/ScaleMatrixDeviceBox.ts:13`).
5. No commits reference #532.

## Analysis
1. No DSP work is needed. Only a persisted mask, a parameter path to the device and an editor control are missing.
2. The mask is relative to `key` in the DSP. A custom grid that shows absolute note names is easier to use. Either store absolute pitch classes and rotate by `key` in the device, or store relative bits and show them relative to the key. Absolute plus forcing key 0 in custom mode is simplest.
3. Changing the `scale` range from 0..7 to 0..8 changes the normalized value of existing automation on `scale`, because `linearInteger` maps the index to 0..1. A separate boolean `custom` field avoids touching existing projects.

## Possible solution
1. Add two new fields to `AutotuneDeviceBox`: `custom` (boolean, automatable) and `notes` (int32, 12 bit mask, default 0xAB5 = C major, not automatable). New field keys, existing projects unchanged.
2. Device crate: bind both. When `custom` is on and `follow` is off, call `set_key(0)` and `set_mask(notes)`. When off, restore key and scale as today.
3. Adapter: expose `custom` as a toggle parameter, `notes` as a plain field.
4. Editor: a Custom toggle next to Follow and a 12 note grid (reuse the `ScaleConfigurator` look), writing `notes` in a transaction. Disable Key and Scale knobs visually while Custom is on, without layout change.
5. Tests: native test in `crates/stock-devices/device-autotune` that a custom mask with four notes corrects to the nearest of them, adapter test for defaults.

## Complexity
