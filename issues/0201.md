## Summary
The reporter likes the current Grain (transient based) stretch but wants an additional "classic" mode: short repeats played very often whose read position moves slowly forward through the sample, giving a smeared sound, plus control over the repeat rate, tempo synced or free in Hz. André explained that today a transient is repeated while playback stays within its range, with segments of about 50 to 180 ms. The reporter then posted a video comparing the current behaviour with the expected one (video exists, not watched). André replied "Yes, that does explain it." The issue was closed once and reopened.

## Current state
1. The Grain mode is `AudioTimeStretchBox` with `transient-play-mode` and `playback-rate` only (`packages/studio/forge-boxes/src/schema/std/timeline/AudioTimeStretchBox.ts:14`).
2. `TransientPlayMode` is `Once, Repeat, Pingpong` (`packages/studio/enums/src/TransientPlayMode.ts:1`), mirrored in the engine (`crates/engine/src/time_stretch.rs:35`).
3. The engine creates one voice per transient segment and loops or bounces it when the timeline needs more output than the segment holds (`crates/engine/src/time_stretch.rs:720`, `RepeatVoice` at `crates/engine/src/time_stretch.rs:274`). Segment boundaries come from the detected transients only.
4. The Once/Repeat/Pingpong buttons are deactivated in the editor for now (`packages/app/studio/src/ui/timeline/editors/audio/TimeStretchEditor.tsx:71`).
5. A Signalsmith phase vocoder mode exists (`packages/studio/forge-boxes/src/schema/std/timeline/AudioSignalsmithBox.ts:10`), which stretches smoothly but is spectral, not the grainy repeat sound in the request.
6. The branch `groove-audio` (`edab9af9e`) touches Grain segment cutting for grooves, not this feature.
7. `plans/enhance-stretcher.md` lists this issue as out of scope. An older analysis is at `plans/issues/201-classic-time-stretch.md`.

## Analysis
The requested sound is a classic granular stretch (as in old samplers): grains of fixed length are started at a fixed rate, each grain reads from the current warped source position, and consecutive grains overlap with a window. The read position advances with the timeline through the warp markers, independent of transients. This is a different timing model from the current transient sequencer, so it fits better as its own voice scheduler than as a fourth `TransientPlayMode`.

## Possible solution
1. Add a new play mode box, for example `AudioGranularBox` (warp markers, grain rate as sync index or Hz with a sync toggle, grain size or overlap, playback rate), parallel to `AudioSignalsmithBox`, so `AudioTimeStretchBox` stays unchanged.
2. In `crates/engine`, add a granular scheduler: at each grain start compute the source position from the warp map at the current timeline position, spawn a windowed grain (Hann) reading at the playback rate, and sum overlapping grains. Reuse `read_interp` and the warp lookup from `crates/engine/src/time_stretch.rs`.
3. Wire the new box in the audio region and clip players and in `StretchSelector.tsx` as a fourth option, with rate and size controls in `TimeStretchEditor.tsx`.
4. Add engine tests for grain timing in sync and Hz, loop and jump behaviour, and the 5 ms jump crossfade.
