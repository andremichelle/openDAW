## Summary
The reporter wants an audio effect at the end of a chain (for example after Vaporisateur) that shapes the volume with an envelope drawn like an automation curve, similar to Bitwig "Segments", and saved with a preset. The attached image shows a breakpoint curve over one bar: a fast drop from full level, then two slower segments down to zero. The reporter suggests "Tidal as a oneshot" or a oneshot option for Tidal. André asked whether it is one cycle of a volume modulation in its own device, the reporter confirmed.

## Current state
1. Tidal is a tempo synced gain LFO whose phase is driven by the song position (`crates/stock-devices/device-tidal/src/lib.rs:4`), so it always repeats. There is no one shot mode and no trigger.
2. Audio effects receive no note events today. A plan for note input on audio effects exists (`plans/audio-effect-note-input.md`, not implemented, no `note-input` field in the schema at `packages/studio/forge-boxes/src/schema/std/DeviceFactory.ts:26`).
3. Project modulators (LFO, Steps, Random, Macro in `packages/studio/forge-boxes/src/schema/std/modulators/`) are song position locked and have no one shot or envelope type.
4. A user can already write such an envelope as a Werkstatt script, but without a drawn curve UI.
5. No commits reference the issue. An older analysis is at `plans/issues/102-volume-envelope-device.md`, it refers to the removed TS processors.

## Analysis
The key design question is what starts the envelope.
1. Per note: shaping each Vaporisateur note needs note events in the audio effect, which is the note input plan. Without it the device cannot know when a note starts.
2. Per bar or per transport start: possible today from `block.p0`, but it is then a slow LFO with a hold, close to what Tidal already does.
3. Per audio onset (an amplitude trigger, like a transient shaper): possible today without note input, but less exact.
The drawn curve needs a compact breakpoint editor inside a device. The timeline value editor (`packages/app/studio/src/ui/timeline/editors/value/`) is bound to timeline geometry, so a device sized canvas editor in the style of the Compressor or Revamp curve views is more likely.

## Possible solution
1. Decide the trigger (questions below). If per note, build `plans/audio-effect-note-input.md` first.
2. Add a new audio effect box (for example `EnvelopeDeviceBox`) with a fixed number of breakpoint fields (time, level, curve) or a pointer hub of point boxes, plus length (synced or ms) and trigger mode.
3. Add a WASM device crate under `crates/stock-devices/` that evaluates the segments per sample, restarts on the trigger and holds the last level after the end, with a short ramp on restart to avoid clicks.
4. Add the adapter, factory entry and a device editor with a breakpoint canvas.
5. Presets work through the existing device preset system, since it stores box fields.

## Complexity
medium. New box schema, adapter and factory (`packages/studio/forge-boxes`, `packages/studio/adapters`, `packages/studio/core`), a new device crate, a device editor in `packages/app/studio`. Large if per note triggering (note input for audio effects) is required.

## Open questions
1. For the reporter: should the envelope restart on every played note, on every bar or loop, or on every detected hit in the audio?
2. For André: a new device, or a one shot mode on Tidal with its slope and symmetry shape instead of a drawn curve?
3. For André: does a fixed number of breakpoints need approval as a limit, or should points be a pointer hub?
