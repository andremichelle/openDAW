## Summary
The reporter wants to separate single drums (kick, snare) of a Playfield into their own track, so they get their own effect chain without parent effects (to avoid phase problems with reverbs, delays, allpass filters, or to add an effect later). Proposal: drag a Playfield pad onto the timeline to create a new track, move all notes that trigger this pad from the Playfield's regions into the new track, and take the pad's own effects along (not the parent's). André replied that pads and Nano are not yet interchangeable and opened #411 for that.

## Current state
1. Blocked on #411 ("Make Nano V2 including all feature of a Playfield slot"), open. The plan is `plans/playfield-nano.md`: pads become `InstrumentCompositeCellBox` cells with a Nano and own chains. Phase 1 (Note Filter MIDI effect, commit 0fe8e500c) is on main. Phases 2 to 6 (Nano gaps, engine routing, schema migration, UI) are open (`plans/playfield-nano.md:161-171`), with open decisions at `:185-193`.
2. A pad drag exists only inside the pad grid: `SlotDragAndDrop` emits `{type: "playfield-slot", index, uuid}` and accepts it only on other pads (`packages/app/studio/src/ui/devices/instruments/PlayfieldDeviceEditor/SlotDragAndDrop.ts:69`, `:84-87`). The timeline drop target accepts only samples and files (`packages/app/studio/src/ui/timeline/tracks/audio-unit/TimelineDragAndDrop.ts:41`).
3. A pad (`PlayfieldSampleBox`) already owns `midi-effects` and `audio-effects` chains, its sample, gate, pitch, start/end and envelope fields (`packages/studio/forge-boxes/src/schema/devices/instruments/PlayfieldDeviceBox.ts:13-56`).

## Analysis
1. To extract a pad into a standalone unit, the new unit needs an instrument that sounds identical to the pad. That is Nano after #411 (with the parity work in the plan), which is why André blocked it.
2. An interim path is possible without #411: create a new Playfield unit holding only this pad (same box type, bit identical sound) and move the pad there. This avoids the Nano parity question.
3. The note split: copy each note region (and clip) of the source unit, keep only notes whose pitch equals the pad's key (`index`), remove those notes from the source, and put the copies on the new unit's note track at the same positions. Regions that share event collections (loops, mirrored regions) need care so a split does not affect other regions unexpectedly.
4. The pad's own effects move with `ProjectApi.moveEffects` (`packages/studio/core/src/project/ProjectApi.ts:364`). Automation on pad parameters lives on the source unit's tracks and must move too.
5. Excluded groups (`exclude`) and choke behaviour across pads break once a pad lives in another unit.

## Possible solution
1. Finish #411 per `plans/playfield-nano.md`, or decide on the interim single pad Playfield.
2. Add a `ProjectApi.extractPad(playfieldBox, padIndex)` that creates the new unit after the source, creates the instrument (Nano with the pad's sample and settings, or a one pad Playfield), moves the pad chains, splits the note events and moves pad automation.
3. Timeline drop: accept `playfield-slot` drags in `TimelineDragAndDrop` (drop between units) and call `extractPad`. Also a context menu entry "Extract to New Track" on a pad.
4. Tests in `studio-core` for the note split (shared collections, loops, clips) and render parity.

## Complexity
large. Depends on #411 (engine, schema migration, UI). The extraction itself touches `ProjectApi`, region and event copying, the Playfield editor and the timeline drop target.

## Open questions

2. Should the notes be moved (removed from the Playfield) or copied with the pad muted in the source?
