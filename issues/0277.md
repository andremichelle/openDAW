## Summary
kaiartikkas wants Werkstatt scripts to receive MIDI notes from clips while the timeline plays (not keyboard input), to trigger an ADSR that modulates the frequency of a ring modulator script. An AI generated code that reads a non existent `block.midi`, and a later attempt modelled on Apparat failed with "TypeError: output is not iterable". André confirmed Werkstatt has no access to MIDI tracks and said he would make a plan.

## Current state
1. Plan written: `plans/audio-effect-note-input.md` (032ad5156), any audio effect can listen to the notes of a chosen instrument track. Not implemented.
2. Schema: key 6 of the audio effect attributes is still reserved (`packages/studio/forge-boxes/src/schema/std/DeviceFactory.ts:32`), no `Pointers.NoteInput` exists.
3. Engine: an audio effect gets no note source, `pull.current = None` (`crates/engine/src/plugin_audio_effect.rs:273` to `:274`).
4. Script bridge: note hooks exist and are kind agnostic. `host_script_note_on` and `host_script_note_off` call `proc.noteOn` and `proc.noteOff` (`packages/studio/core-wasm/src/script-bridge.ts:218` to `:219`, `:398` to `:405`), today used by Apparat only. The Werkstatt crate never calls them (`crates/stock-devices/device-werkstatt/src/lib.rs:140`).

## Analysis
1. Audio effects are fed audio only. Notes come from a unit's `NoteSequencer` and reach instruments and MIDI effects, not effects.
2. The plan adds a `note-input` pointer on every audio effect, a fresh `NoteSequencer` over the source unit's tracks inside `PluginAudioEffect`, and an abi `handle_event` with a no-op default, so stock effects stay bit identical.
3. Werkstatt then only needs to forward events to the existing script hooks, so user scripts get `noteOn(pitch, velocity, cent, id)` and `noteOff(id)` like Apparat, with sample accurate block splits.
4. Workaround today: none for timeline notes. A modulator (LFO, Steps) can modulate a Werkstatt param, but not from notes.

## Possible solution
1. Implement `plans/audio-effect-note-input.md`: schema key 6 `note-input` with `Pointers.NoteInput` accepted by `AudioUnitBox`, `PluginAudioEffect` pull chain, abi `AudioEffect::handle_event`.
2. In `device-werkstatt`, split blocks at events and call `host_script_note_on/off` for each note event.
3. "MIDI Input" menu in the Werkstatt editor header listing instrument tracks.
4. Document `noteOn` and `noteOff` for Werkstatt in the scripting manual and the default AI prompt, so generated code stops inventing `block.midi`.
5. Tests per the plan: an effect with a chain receives note on/off at the right offsets, an effect without one renders bit identical.

## Complexity
large. Schema change on all audio effects (forge-boxes, generated Rust registry), engine (`plugin_audio_effect.rs`, wiring), abi, the Werkstatt crate, editor menu, manual. Cross-layer, shared with the WebCLAP note input use case (Mango).
