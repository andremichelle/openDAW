## Summary
André filed ideas from a community member on podcast support, modelled after Ultraschall:
1. Track roles (host, guest, soundboard), workflow stages (prepare, record, edit).
2. Chapter markers with images and links that stay anchored when the timeline is edited, and export with chapter metadata (ID3 and similar).
3. A soundboard, a per channel cough button addressable via MIDI, Auphonic integration.
4. Voice effects: deesser, leveler, LUFS meter, true peak limiter, ducking, broader dynamics.
5. Architecture questions: how multi hour multitrack recordings behave given float32 in RAM and tab memory ceilings, what happens to a running recording if the browser crashes, and whether a native capture backend (CoreAudio into a dedicated AudioWorklet) could replace `getUserMedia`.

## Current state
1. Recording keeps the whole take in memory. `RecordingWorklet` pushes every ring buffer chunk into `#output` (`packages/studio/core/src/RecordingWorklet.ts:40` and `:75`) and only writes the sample when the take is finalized. Stereo float32 at 48 kHz is about 384 KB per second per track, so a two hour, three track session is several GB in the tab. A tab crash loses the take.
2. The capture rewrite introduced an input port abstraction, `AudioInputPort` (`packages/studio/core/src/io/AudioInputPort.ts:26`), with the browser implementation in `packages/studio/core/src/io/browser/BrowserAudioInput.ts`. A native input could be another implementation of this interface. The Tauri desktop shell is planned in `plans/tauri.md` and only wraps the web build so far.
3. Markers exist as `MarkerBox` (`packages/studio/forge-boxes/src/schema/std/timeline/MarkerBox.ts:8`) with position in ppqn, label and hue. No image or link fields, no chapter export. No ID3 or chapter code exists in `packages/studio/core/src` or `packages/app/studio/src`.
4. Effects already present: Compressor and Gate with side chain input (`packages/studio/forge-boxes/src/schema/devices/audio-effects/CompressorDeviceBox.ts:46`, `GateDeviceBox.ts:33`), so ducking works by side chain today. Maximizer (limiter), Mastering. A LUFS readout exists in the analysis level card (`packages/app/studio/src/ui/analysis/LevelCard.tsx:13`) backed by a loudness meter in core-wasm (`packages/studio/core-wasm/test/loudness-meter-ebu.test.ts`). No deesser, leveler or true peak limiter.
5. Extension mechanisms that exist: scriptable devices (Werkstatt, Apparat, Spielwerk) and WebCLAP plugins. There is no skin or UI plugin mechanism.
6. An older analysis with per feature notes is in `plans/issues/245-podcast-recording.md`. No commits reference #245.

## Analysis
1. This is a roadmap, not a single feature. The pieces are independent and of very different size.
2. The only blocking piece for long sessions is streaming capture to storage. Without it, multi hour multitrack takes risk tab memory limits and are lost on a crash.
3. Chapter markers anchored in ppqn already move with the musical timeline. Ripple edits (see `plans/ripple-delete.md`) decide whether they follow cuts.
4. A native capture backend needs clock alignment between the native ring buffer and the AudioWorklet graph. The `AudioInputPort` seam plus the existing recording latency model (`packages/studio/core/src/io/RecordingLatency.ts`) is the natural place. The simpler path, native record then import on stop, avoids the clock problem but gives no monitoring through the studio.

## Possible solution
1. Split into separate issues: streaming capture, chapter markers and export, soundboard, cough button, Auphonic, each voice effect.
2. Streaming capture first: flush `RecordingWorklet` chunks incrementally to an OPFS file through the OPFS worker, keep only peaks and a small tail in memory, and rebuild a take from the OPFS file after a crash on the next start.
3. Chapter markers: add new fields (image, link) to `MarkerBox` or a separate chapter marker box, and write chapters in the export encoder (FFmpeg supports chapter metadata).
4. Voice effects as new stock devices in the WASM engine: deesser (side chain band compressor), leveler (slow automatic gain), true peak limiter (oversampled detection in the Maximizer).
5. Cough button: a momentary mute bound to a MIDI note on a channel strip.
6. Native capture: a desktop only `AudioInputPort` implementation once the Tauri shell has native audio.

## Complexity
large. Recording pipeline (studio-core capture, OPFS worker), box schema (markers), export (FFmpeg), new WASM devices (crates/engine, adapters, editors), desktop shell for native capture.
