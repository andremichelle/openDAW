## Summary
Code cannot be reused between scripts without copy and paste. André proposes source files stored in a library that scripts can refer to and that are included when compiling. A follow up comment adds that the editor should read their types and auto complete them.

## Current state
1. Device scripts (Werkstatt, Apparat, Spielwerk) are compiled by `ScriptCompiler`: the user code is wrapped (`packages/studio/adapters/src/ScriptCompiler.ts:265`), validated with `new Function` (`:320`) and stored inline in the device box `code` field (`:411`). There is no include or import mechanism.
2. Studio level scripts (the code editor page) are stored in OPFS under `scripts/v1/<uuid>/script.ts` (`packages/studio/core/src/scripts/ScriptPaths.ts:4`, `packages/studio/core/src/scripts/ScriptStorage.ts`), listed in `packages/app/studio/src/script/ScriptBrowser.tsx`.
3. Monaco setup: the device editors use the JavaScript defaults with one extra lib for `sampleRate` (`packages/app/studio/src/ui/code-editor/monaco-setup.ts:12`). The code editor page uses TypeScript defaults with `library.d.ts` and the API declarations as extra libs (`packages/app/studio/src/ui/pages/code-editor/monaco-setup.ts:38`).
4. A related draft plan for per script data storage exists (`plans/script-storage.md`, issue #487), not implemented. No commits reference this issue.

## Analysis
1. Projects must stay self contained: a project opened on another machine, in a live room, or exported as a bundle has no access to the local library. So included sources must be resolved at compile time and stored in the device box, either inlined into `code` or as separate fields holding a snapshot of each included file.
2. Inlining loses the link, so later edits to a library file would not reach existing devices unless they are recompiled. A stored snapshot plus the library file id allows an "update from library" action.
3. The engine receives one wrapped source string per device (registered in the worklet scope, `packages/studio/adapters/src/ScriptCompiler.ts:322`). Concatenation at compile time keeps the engine untouched.
4. For auto completion, each library file can be added to Monaco with `addExtraLib` under a stable file name. For JavaScript device editors, JSDoc types in the library files would be picked up, real TypeScript types would need the device editors to switch to TypeScript or to a transpile step.

## Possible solution
1. Storage: a `scripts/lib/<name>.js` folder in OPFS (or a "library" kind in `ScriptStorage`), with a list and editor in the script browser.
2. Directive: `// @include <name>` lines at the top of a script, parsed in `ScriptCompiler` like the existing header tags.
3. Compile: resolve each include from the library, concatenate before the user code inside the wrapper, and store the resolved source in the device box (inline with markers, or a new string field per include) so the project stays portable.
4. Editor: register every library file with `addExtraLib` in both Monaco setups, and refresh them when a library file changes.
5. Optional: an "update includes" menu action on a device that re-resolves its includes from the local library.
6. Tests in `packages/studio/adapters/src/ScriptCompiler.test.ts` for include resolution, missing includes (compile error with the name), and recursion.

## Complexity
medium. `packages/studio/adapters/src/ScriptCompiler.ts`, OPFS storage in `packages/studio/core/src/scripts`, script browser and both Monaco setups in `packages/app/studio`. Schema change only if includes get their own fields.
