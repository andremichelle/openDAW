## Summary
If the studio is closed and the "Leave site?" dialog is ignored, unsaved edits are lost. André asks for a backup (IndexedDB named in the title) and an offer to restore the last project on the next start.

## Current state
1. A backup mechanism exists: `Recovery` writes `uuid`, `project.od`, `meta.json` and `saved` to OPFS under `.backup` (`packages/studio/core/src/project/Recovery.ts:38`) and reads and deletes it in `restoreProfile` (`packages/studio/core/src/project/Recovery.ts:16`).
2. The backup is only written from the crash dialog: `ErrorHandler` gets `service.recovery.createBackupCommand()` (`packages/app/studio/src/boot.ts:148`) and passes it as `backupCommand` (`packages/app/studio/src/errors/ErrorHandler.ts:354`).
3. `#configBeforeUnload` only calls `preventDefault` when there are unsaved changes, it writes nothing (`packages/app/studio/src/service/StudioService.ts:588`).
4. On every boot `#checkRecovery` restores a found backup silently, without asking (`packages/app/studio/src/service/StudioService.ts:598`).
5. No commits reference the issue. An older analysis is at `plans/issues/084-autosave-indexeddb.md`, its line numbers are outdated but the findings still hold.

## Analysis
1. An unload handler cannot wait for the asynchronous OPFS worker writes, so a write in `beforeunload` is not reliable. The backup must already exist when the tab closes.
2. OPFS is already the persistence layer and survives closing the browser, so IndexedDB adds nothing.
3. A single `.backup` slot means two tabs overwrite each other's backup.
4. `ProjectProfile.hasUnsavedChanges()` (`packages/studio/core/src/project/ProjectProfile.ts:101`) and the box graph update subscription (`packages/studio/core/src/project/ProjectProfile.ts:56`) give the trigger for a debounced write.

## Possible solution
1. In `StudioService`, subscribe to the active profile's edits and write the backup debounced (for example a few seconds after the last edit) while `hasUnsavedChanges()` is true. Also write on `visibilitychange` to hidden and on `pagehide`.
2. Delete the backup after a successful save, so a clean exit leaves nothing behind.
3. Change `#checkRecovery` to show a dialog ("Restore unsaved changes of <project name>?" with Restore and Discard) instead of restoring silently. Only delete the backup after the choice.
4. Keep the crash dialog path, it writes into the same slot.
5. Optionally key the backup by project uuid to avoid two tabs clobbering each other.
6. Test with a unit test for `Recovery` and a manual check: edit, kill the tab, reopen, see the offer.

## Complexity
small. `packages/app/studio/src/service/StudioService.ts`, `packages/studio/core/src/project/Recovery.ts`, one dialog in `packages/app/studio/src/ui/components/dialogs.tsx`.
