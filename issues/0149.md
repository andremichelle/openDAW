## Summary
Vaporisateur has a single envelope that drives both the VCA and the filter cutoff. The reporter wants a separate filter envelope like most synths. André replied that one shared envelope for VCA and VCF was common in vintage synths and left the issue open for comments. A second user agreed and also asked for a clearer editor layout, with coloured zones for ADSR and oscillator sections (he liked the Delay editor).

## Current state
1. Schema has one ADSR: `attack` 16, `release` 17, `decay` 19, `sustain` 20, and a bipolar `filter-envelope` amount 18 (`packages/studio/forge-boxes/src/schema/devices/instruments/VaporisateurDeviceBox.ts:34`, `:42`). A `version` field 99 exists for migrations (`VaporisateurDeviceBox.ts:171`).
2. Engine: each voice runs one `Adsr` (`crates/stock-devices/device-vaporisateur/src/voice.rs:97`), renders it into `work.vca` (`voice.rs:137`) and uses the same buffer for the cutoff: `cutoff = flt_cutoff + keyboard + vca * flt_env_amount + lfo * lfo_target_cutoff` (`voice.rs:146`).
3. Editor: `packages/app/studio/src/ui/devices/instruments/VaporisateurDeviceEditor.tsx`.
4. Nothing started for this issue.

## Analysis
This is a design choice, not a bug. A second envelope is additive: new fields for filter attack, decay, sustain, release, plus a switch or default that keeps old projects on the shared envelope so they sound the same.

## Possible solution
1. Add filter envelope fields (attack, decay, sustain, release) and a boolean `filter-envelope-separate` (default false) to `VaporisateurDeviceBox` with new keys.
2. Adapter: expose the new parameters in the Vaporisateur box adapter.
3. Engine: add a second `Adsr` per voice in `voice.rs`, render it into its own scratch buffer when the switch is on, and use that buffer at `voice.rs:146`. When off, keep the current path so existing projects stay identical.
4. Mirror the field keys in the crate's parameter mapping and the wasm parity test.
5. Editor: a filter envelope section, shown with the switch, in the existing layout without layout jumps. The colour zone request from the comments is a separate UI rework.
6. Scripting and SDK facade: add the new fields.

## Complexity
medium. forge-boxes schema, adapters, `crates/stock-devices/device-vaporisateur` (voice and shared settings), editor, scripting, parity tests.
