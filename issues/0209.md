## Summary
Request to add the Paulstretch algorithm (Paul's Extreme Sound Stretch by Paul Nasca) as a native processing effect. It stretches audio by extreme ratios without the rhythmic artefacts of grain based stretchers and is common for ambient music and sound design. Audacity has it built in.

## Current state
1. Nothing Paulstretch related exists in the code or in any branch or commit.
2. A pattern for offline audio processing exists: "Convert to Mono..." in the region context menu (`packages/app/studio/src/ui/timeline/tracks/audio-unit/regions/RegionContextMenu.ts:168`), a dialog in `packages/app/studio/src/service/MonoConversions.ts:10`, and the processing plus file replacement in `packages/studio/core/src/AudioMonoConversion.ts:16` (mixdown) and `:58` (convert, `replace` keeps or replaces the original `AudioFileBox`).
3. An FFT exists in TypeScript (`packages/lib/dsp/src/fft.ts`) and in Rust (`crates/stretch/src/fft.rs`).
4. The engine's real-time time stretch (`crates/stretch`, Signalsmith) is for tempo following, not extreme ratios.

## Analysis
1. Paulstretch output is many times longer than its input, so it cannot be a real-time insert effect in a chain that runs in sync with the timeline. It is an offline render that produces a new sample, as in Audacity.
2. The algorithm is short: windowed FFT frames read with a hop of `window / (2 * stretch)` on the input, magnitudes kept, phases randomised, inverse FFT, overlap-add with a hop of `window / 2` on the output. Parameters: stretch factor and window size (time resolution). Output length is `input length * stretch`.
3. Long outputs (for example 30 s stretched 50x is 25 minutes) need progress, cancel and probably a worker, plus a length warning.

## Possible solution
1. `AudioPaulstretch` in `packages/studio/core/src/` beside `AudioMonoConversion`: `render(audioData, stretch, windowSeconds): AudioData`, per channel, using `lib-dsp` FFT, run in a worker with progress.
2. A dialog with stretch factor, window size, resulting length readout and "keep original", modelled on `MonoConversions.convertRegion`.
3. A "Paulstretch..." entry in `RegionContextMenu.ts` for audio regions. The result is imported as a new sample, the region points to it and its duration grows to the new length.
4. Tests: output length, silence in gives silence out, energy roughly preserved for a sine.

## Complexity
medium. New DSP in `packages/studio/core` (or `lib-dsp`), a worker, a dialog and a context menu entry in `packages/app/studio`. No engine, schema or ABI change.

## Open questions
1. Is an offline region process acceptable, or does the reporter expect a real-time device (for example a freeze style effect that holds the current sound)?
2. Should it also be available in the sample editor, not only on regions?
