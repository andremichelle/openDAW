## Summary
Two problems in the clip launcher:

1. A clip moved to the right lands in columns that are not visible and could only be reached by widening the clip view or undoing the move (first GIF, only the first frame was viewed: a "Notes" clip dragged past the last visible column).
2. The clip view resizer can be dragged wider than the browser window, so the region/track view becomes unreachable (second GIF, first frame: the clip view at one column, arrangement visible).

André prefers a horizontal slider for the clips. Felipe opened PR #425 (column scrolling, closed), which was folded into PR #451 "Resize timeline tracks and smoothly scroll the clip view" (merged 2026-10-14).

## Current state
1. Point 1 is largely solved. The clip view scrolls by pixels with the trackpad, Shift+wheel and edge auto scroll during drags (`packages/app/studio/src/ui/timeline/tracks/audio-unit/clips/ClipScroll.ts:9`, `packages/app/studio/src/ui/timeline/tracks/audio-unit/clips/ClipsArea.tsx:137`). Columns grow to the highest clip index plus two on every rebuild (`packages/app/studio/src/ui/timeline/tracks/audio-unit/clips/ClipLane.tsx:120`), so a clip moved far right is reachable by scrolling. Commits: f302d1d97 (smooth horizontal scrolling), cded480c1.
2. There is no visible horizontal scrollbar for the clip columns. The only `Scroller` in the timeline is the vertical one (`packages/app/studio/src/ui/timeline/tracks/audio-unit/AudioUnitsTimeline.tsx:109`). Users without a trackpad must know Shift+wheel.
3. Point 2 is still open. The resizer sets `clips.count` with no upper bound (`packages/app/studio/src/ui/timeline/tracks/audio-unit/clips/ClipsHeader.tsx:106` to `:117`), and the grid uses `repeat(var(--clips-count), ...)` (`packages/app/studio/src/ui/timeline/Timeline.sass:18`), so the regions column can be pushed out of the window.
4. Leftovers: `TracksManager.maxClipsIndex` is a constant 8 that is never updated (`packages/app/studio/src/ui/timeline/tracks/audio-unit/TracksManager.ts:91`), and the move modifier clamps the delta (not the index) to it (`packages/app/studio/src/ui/timeline/tracks/audio-unit/clips/ClipMoveModifier.ts:93`), so one drag moves at most 9 columns right. Boot still derives the count from `getMinFreeIndex()`, the first gap, not the highest index (`packages/app/studio/src/service/StudioService.ts:496`).
5. Plan: `plans/clip-scrolling.md` (16b3de789), written for column snapped scrolling, partly superseded by the pixel scrolling of #451.

## Analysis
1. Shadowed space no longer traps clips because scrolling exists, but discoverability needs the slider André asked for.
2. The overflow comes from the resizer drag having no `fit` clamp. The plan defines it as `floor((timelineWidth - headerWidth - MinRegionsWidth) / ClipWidth)`. The PR #425 review also asked to keep the requested count and clamp only the displayed count, so a window resize does not lose it.

## Possible solution
1. In the resizer `update` (`ClipsHeader.tsx:110`), clamp `newValue` to the fit computed from the timeline element width, the header width and a minimum regions width.
2. Clamp the displayed count to the fit on window resize as well (watch the timeline element), keeping the requested `clips.count` untouched so it comes back when the window grows.
3. Add a horizontal `Scroller` under the clip columns (footer row, `TracksFooter`), fed in pixels: content `columns * ClipWidth`, visible `count * ClipWidth`, position `clips.scroll`. Hide it when all columns fit.
4. Replace the constant `maxClipsIndex` clamp in `ClipMoveModifier.update` with a lower bound only (index >= 0), since columns grow on rebuild.
5. Boot: use the highest `indexField` instead of `getMinFreeIndex()` in `StudioService.ts:496`.

## Complexity
medium. `ClipsHeader.tsx`, `Timeline.tsx`, `TracksFooter`, `ClipMoveModifier.ts`, `StudioService.ts`, all in `packages/app/studio`. No engine or schema change.
