## Summary
The reporter sequences external gear with a MIDI Output device and listens to it through an audio input with monitoring (Tape with monitoring). The returning sound is late by roughly twice the studio latency, about 150 ms at a reported 75 ms latency. Delaying every other track by hand (Werkstatt delays) is fragile because the latency varies between 50 ms and 140 ms. The request is built in compensation that delays all tracks except the ones that go out to hardware and come back. A follow up comment adds that several hardware tracks may have different latencies and tracks that are already compensated must not be delayed again.

## Current state
1. MIDI Output notes are scheduled against the audio output clock plus a per device `delayInMs` (`packages/studio/forge-boxes/src/schema/devices/instruments/MIDIOutputBox.ts:13`, range 0 to 500 ms, default 10). So a note leaves at the moment the internal mix is heard, plus that delay.
2. Commit 389224d34 (#356) fixed MIDI output jitter: notes were timed from when the main thread picked them up, so a busy page delayed them by varying amounts. Notes now carry their exact audio time. This likely removed a large part of the varying 50 to 140 ms the reporter saw.
3. Plugin delay compensation is implemented in the WASM engine for latent devices (df8c72f90, 1bfbdcb50, 54ac2db89, #482). Design and status in `plans/delay-compensation.md`. Junction delays align paths at buses, the total PDC is exported as `engine.compensationLatency` (`packages/studio/core/src/Engine.ts:78`). Phase 4.3 of that plan delays MIDI out by total PDC. Phase 7 (monitoring) is open.
4. Recording is aligned already: `RecordAudio` subtracts output, input and compensation latency from the take (`packages/studio/core/src/capture/RecordAudio.ts:124`). The problem is only what is heard while monitoring.
5. No commits reference #355.

## Analysis
1. The round trip while monitoring is: internal mix rendered at time T and heard at T + output latency. The MIDI note leaves at T + output latency + `delayInMs`. The gear's audio enters with input latency, is monitored through the engine and leaves with output latency again. Result: hardware is heard at T + 2 x output latency + input latency + `delayInMs`, internal tracks at T + output latency. This matches the reporter's "latency times two".
2. Sending MIDI earlier cannot fix it, the required send time (T minus input latency) is already in the past when the engine renders T. The engine does not render ahead.
3. The fix is the PDC model in reverse: a monitored external instrument is a source with a known extra arrival (`delayInMs` + input latency + output latency on the return). All other paths get delayed to that arrival at the master junction, and the playhead and MIDI out shift by the same total, like PDC phase 4.
4. The cap `MAX_COMPENSATION_SECONDS` (0.1 s) in `plans/delay-compensation.md` would be too small for a 150 ms round trip.
5. Different hardware latencies per track (comment) fall out of the max at each junction: the latest path sets the total, earlier ones get delayed, a compensated path is not delayed again.
6. The browser reports output latency (`AudioContext.outputLatency`) but input latency only through calibration (`packages/studio/core/src/capture/InputLatency.ts:13`), so the round trip is only accurate after a calibrated measurement.

## Possible solution
1. Ask the reporter to retest after the #356 fix to see whether the variation is gone.
2. Model a monitored capture whose instrument receives notes from a MIDI Output unit as a latent source: arrival = `delayInMs` + measured input latency + output latency. Add it as a new term in `Engine::compensate_latencies()` (crates/engine).
3. Raise or make configurable the compensation cap for this source.
4. Apply the total to the playhead, MIDI Output scheduling and recording offsets as PDC phase 4 already does.
5. Alternatively a simpler manual version: a per capture "external latency" value in ms that the PDC pass treats as that unit's arrival, with a "measure round trip" helper using the existing calibration.
6. Engine tests with a fake round trip: impulse on an internal track and via an external loop arriving aligned at the master.
