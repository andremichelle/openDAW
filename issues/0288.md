## Summary
The reporter wants to put any instrument (Apparat, Vaporisateur) on a Playfield pad, so a pad can play synthesized sounds, and Nano should get the Playfield sample features. André proposed an Instrument Composite with a note filter per layer. The reporter answered that each pad must only react to its own note, assigned automatically to the next free note when a chain is added, and pads without an instrument must stay silent. He also asked for a drum key layout in the note editor: two screenshots (viewed) show a normal piano roll and a drum view that lists only the used notes as named rows ("14\"Crash", "18\"BCrMtd" and so on). #141 can be closed according to the reporter, #85 should be solved by the same work.

## Current state
1. Instrument Composite exists: `InstrumentCompositeBox` and `InstrumentCompositeCellBox` (`packages/studio/forge-boxes/src/schema/devices/instruments/InstrumentCompositeCellBox.ts`) with per layer MIDI and audio effects, meters, nesting, MIDI Output layers (commits `9299675c0`, `370fbe12c`, `2c7eafae9`, `6eb0f78a5`). Every layer receives every note.
2. Note Filter MIDI effect is on main (`0fe8e500c`): `NoteFilterDeviceBox` with min, max, transpose, key, crate `crates/stock-devices/device-note-filter`. A layer can already be limited to one key manually.
3. Nano gained Mono/Poly, Pan, One-Shot, Fixed and voice stealing (`0aa4db2d8`, #467) to take over the Playfield slot player.
4. `plans/playfield-nano.md` describes turning every pad into a composite cell holding Nano (phase 1 done, phases 2 to 5 open) and, as phase 6, any instrument on a pad (`plans/playfield-nano.md:161`). Pad routing uses the cell `index` as pad key and a per pad `key` for the played pitch.
5. Drum key layout: `plans/drum-editor.md` (commit `3d762de77`) plans a note editor variant that shows sound names per pitch when the instrument provides a mapping. That commit is on branches `follow-live-room`, `groove-audio`, `guitar`, not on main. No code yet.

## Analysis
The requested behaviour equals `plans/playfield-nano.md` goal 5: pads as cells with routing by key, empty keys silent. The engine already builds cells (`build_cell`) but has no note routing for cell based composites (plan section "Where we are", item 4). The automatic next free note assignment maps to creating a cell with the next unused `index`. The drum view plan keeps all 128 rows, while the reporter's mockup shows only used notes, a difference to decide.

## Possible solution
1. Finish `plans/playfield-nano.md` phases 2 to 5 (Nano parity, cell based Playfield routing in the engine, schema migration, UI).
2. Phase 6: allow any instrument in a pad cell (device browser on a pad), label from the instrument, new pads take the next free key.
3. Implement `plans/drum-editor.md` on main, with a mapping provider from the Playfield cells, and decide whether unused rows are hidden.
4. Close #141 and, after the pad work, #85.
