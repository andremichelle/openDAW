## Summary
Importing a percussion soundfont (`HD_Percussion.sf2`) fails. The screenshot shows the dialog "Soundfont Import Issues" with "Error: Missing required 'INAM' sub-chunk could not be imported." Other .sf2 files work. André attached the file (`HD_Percussion.sf2.zip`, 5.5 MB) to the thread.

## Current state
1. The screenshot and the zip were downloaded and inspected. The file was saved by Polyphone. Its INFO list contains `ifil` (2.1), `isng` "EMU8000", `INAM` with size 2 and content `\0\0` (an empty name), and `ISFT` "Polyphone".
2. The parser is the `soundfont2` npm package 0.5.0. `node_modules/soundfont2/src/chunk.ts:52` checks `if (!info.INAM)`, so an empty string name throws the same error as a missing chunk.
3. Verified in node: parsing the original file throws "Missing required 'INAM' sub-chunk". With the first INAM byte replaced by `?` the same file parses fine (1 preset, 1 instrument, 31 samples).
4. All parsing goes through `ExternalLib.SoundFont2` (`packages/studio/core/src/ExternalLib.ts:13`), constructed in three places: import `packages/studio/core/src/soundfont/SoundfontService.ts:66`, and loading `packages/studio/core/src/soundfont/DefaultSoundfontLoader.ts:58` and `:90`. The import uses `soundFont2.metaData.name` as the soundfont name (`SoundfontService.ts:68`).
5. The error text comes from `AssetService.importFiles` (`packages/studio/core/src/AssetService.ts:154`).

## Analysis
Root cause is the library's falsy check on the name. The file is valid enough (INAM exists, it is just empty, and the spec requires it to be zero terminated, which it is). Fixing the library itself is not possible without patching node_modules (the repo has no patch-package setup).

## Possible solution
1. Add a helper in `packages/studio/core/src/soundfont/` (for example `SoundfontParser.parse(SoundFont2, bytes)`) that scans the RIFF `LIST INFO` chunk. If `INAM` exists with an empty first byte, parse a copy of the bytes with the first byte set to a placeholder character (size unchanged, so no RIFF rewrite). If `INAM` is missing entirely, rebuild the INFO list with an inserted INAM chunk and fix the RIFF and LIST sizes.
2. Use the helper in all three construction sites (`SoundfontService.ts:66`, `DefaultSoundfontLoader.ts:58`, `:90`). Keep the stored file and the sha256 UUID based on the original bytes.
3. At import, use the file name without extension as the name when the metadata name is empty or the placeholder (`AssetService.ImportArgs` carries `name`, see `AssetService.ts:139`).
4. Unit test with a minimal synthetic sf2 (empty INAM and missing INAM cases).
5. Comment on the issue once deployed.

## Complexity
small. One parsing helper plus three call sites in `packages/studio/core/src/soundfont/`, and one test. No engine or schema change.
