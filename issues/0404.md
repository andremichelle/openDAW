## Summary
Sometimes the "Loading..." dialog never closes when opening a project, from the dashboard or while another project is open. Typical flow: open a project, edit, save, open another project. Reloading the page fixes it. Not project specific, Chrome 148. The screenshot (viewed) shows the dashboard project list behind a "Loading..." dialog. André found that the cloud sample index sometimes stalled and project loading waits for it, fixed in `16da05f89` with indefinite retry. The reporter still saw the hang. André then added debug logging (2026-10-12) and asked for the console output next time. No reply since.

## Current state
1. `16da05f89` added `fetchIndex` with a 10 second per attempt timeout and endless retries (`packages/app/studio/src/opendaw-api/IndexFetch.ts:17`), used by the sample and soundfont APIs.
2. `7991ff5ed` added `[ProjectLoad]` traces per stage in `ProjectProfileService.load` (`packages/app/studio/src/service/ProjectProfileService.ts:148`), in the catalogue collection of `SampleService` and `SoundfontService`, in the index retry, and in `migrateAudioFileBox`.
3. The dashboard handler shows a modal "Loading..." without cancel and waits for the full load (`packages/app/studio/src/ui/dashboard/Resources.tsx:57`).

## Analysis
Root cause is not confirmed after the first fix. Stages that can still wait forever:
1. The index fetch retries forever by design (`IndexFetch.ts:7`), so a permanently failing index still looks like a hang, now with console messages.
2. Old projects that need `migrateAudioFileBox` wait for a sample loader to reach `loaded` or `error` (`packages/studio/core/src/project/ProjectMigration.ts:74`). A loader stuck in progress never settles, there is no timeout.
3. `WclapMissing.resolve` (`packages/app/studio/src/service/WclapMissing.ts:10`) loads missing plugins from the cloud and may open dialogs.
4. `ProjectStorage.loadProject` and `loadCover` read OPFS, which can block if another tab holds a handle.
The traces from `7991ff5ed` show which stage is the last one reached.

## Possible solution
1. Ask the reporter again for the console output (filter `[ProjectLoad]`) when it happens.
2. Show the current stage in the Loading dialog and add a Cancel button, so the user is never stuck and the stage is visible in a screenshot.
3. Once the stage is known, add a timeout or a failure path for that stage.

## Complexity
unknown until the stalled stage is known. Items 2 and 3 are small each (`Resources.tsx`, `ProjectProfileService.ts`, the stalled loader).
