## Summary
The reporter wants to copy and paste synths and clips between projects and to merge a whole project into another. Audiotool and Bitwig allow several projects open at once with data moving between them. André answered that copy and paste in openDAW already survives a project switch and works across browser instances.

## Current state
1. The clipboard encodes entries as text `OPENDAW:2:<type>:<base64>` in the system clipboard plus an in memory fallback (`packages/studio/core/src/ui/clipboard/ClipboardManager.ts:31`, `:61`). Handlers exist for devices, modulators, regions, notes, values and audio units (`packages/studio/core/src/ui/clipboard/types/`). This already covers copying synths (audio units, devices) and clips or regions from one project to another after switching, or between two browser tabs with different projects.
2. `TransferAudioUnits.transfer` copies audio units with all dependencies into any target `ProjectSkeleton`, sharing preserved resources already present (`packages/studio/adapters/src/transfer/TransferAudioUnits.ts:21`). It is already used across graphs by "Extract AudioUnit Into New Project" (`packages/app/studio/src/ui/timeline/tracks/audio-unit/headers/TrackHeaderMenu.ts:92`).
3. There is no "merge project into current" command and only one project open per tab.
4. Samples and soundfonts live in shared OPFS storage keyed by UUID, so references survive within one browser. Across machines the pasted boxes reference samples that may be missing locally.

## Analysis
1. Copy and paste between projects is effectively done (two tabs, or switch projects). The request mostly reduces to the merge case.
2. Merging a project: decode the other project (`ProjectSkeleton.decode`, see `packages/studio/core/src/project/Project.ts:127`) and transfer all its non Output audio units into the current skeleton via `TransferAudioUnits.transfer`. Regions on their tracks come along unless `excludeTimeline` is set. Open design questions: what happens with the other project's tempo, signature, markers, loop area, key and chord tracks, and its master chain (Output is skipped on purpose, `TransferAudioUnits.ts:24`). Aux and bus units need `includeAux` and `includeBus`.
3. Several open projects in one tab is a much larger change: `StudioService` holds one project, one engine and one editing history. Not needed for the stated use cases given the two tab workaround.

## Possible solution
1. Add a project browser context menu entry "Merge into Current Project" (`packages/app/studio/src/project/ProjectBrowser.tsx:87` is where entries live).
2. Load the selected project's bytes, decode the skeleton, and in one `editing.modify` call `TransferAudioUnits.transfer(allNonOutputUnits, project.skeleton, {includeAux: true, includeBus: true})`, appended after existing units.
3. Optionally offer an insert position (at playhead or at the end of the current arrangement) by offsetting region positions.
4. Leave tempo, signature and markers of the target untouched. Document this in the manual.
5. Tests: merge two skeletons, check routing to the primary bus, shared resources not duplicated, undo restores.

## Complexity
large for multiple simultaneous projects. The merge command alone is medium: one menu entry plus loading and transfer in `packages/app/studio/src/project/` and tests around `TransferAudioUnits`.

## Open questions

2. For André: on merge, which timeline data of the source project (tempo, signature, markers, harmony tracks) should be ignored or offered?
3. For the reporter: does copy and paste between two tabs cover the synths and clips part for you?
