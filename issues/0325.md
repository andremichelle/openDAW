## Summary
Gabriel (vigliensoni) asks for synced listening in live rooms. Today transport is local to each tab. He proposed a shared transport anchor in a Yjs map (`playing`, `epoch`, `anchorPosition`, `bpm`), last action wins, an opt in "follow room playback" toggle, quantized rejoin and drift tolerance of about 150 to 200 ms, and has a working implementation in PR #326. His screenshot shows his prototype: a headphone toggle with the tooltip "Follow Room Playback" next to the loop button in the transport bar, and headphone icons next to the two synced users ("Uganda", "Ghana") in the room status bar of room 'tutito'. André preferred fewer UI elements and asked for use cases. Gabriel listed three: remote rehearsal with a collaborator abroad, remote mixing (replacing Zoom plus Audiomovers), and teaching small teams in a classroom on headphones. On 2026-11-02 André (via Claude) announced Follow Playback on DEV and asked Gabriel to test it across two machines. No reply yet.

## Analysis
The feature request is covered by a different design than the one proposed: following a person rather than a room wide last action wins transport. It covers all three use cases (one person drives, others listen). Deliberate omissions: no periodic resync or drift correction, count-in is not forwarded to followers. Drift over long playback on machines with different audio clocks is the main unknown, since each engine runs freely after the start.

## Possible solution
1. Wait for Gabriel's two machine feedback on PROD (or DEV).
2. If drift is reported, add a periodic `state` push from the leader while followed and nudge the follower only when the offset exceeds a threshold (the tolerance idea from the issue).
3. Close PR #326 with a pointer to the merged design, then close this issue.

## Complexity
small. Remaining work is feedback handling. An optional drift correction would touch `packages/app/studio/src/follow/FollowService.ts`, `FollowMath.ts` and their tests.
