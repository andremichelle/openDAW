# Learn Key: control a parameter with a computer key

Minimal key mapping next to MIDI learning. Right-click a parameter, "Learn Key...", press a key. A key mapping
has two modes, chosen in the parameter's context menu under "Key Mode":

- Toggle (default, like Ableton Live): each press switches between the mapped min and max, release does nothing.
- Momentary: the parameter receives 127 (its mapped max) while the key is held and 0 (its mapped min) on release.

Map mode, colours and the mapping list stay MIDI only in this PR (see Roadmap).

| 2   | Key Map Mode: own colour, header entry, key source indicator | `MapTarget`, `mapMode`/`mapTarget`, map mode sass      |
| 3   | Key mappings in the mapping panel, preset export, manual     | `MIDIMappingPanel` list, search, sort, delete, Min/Max |

- **PR 2:** `mapMode` becomes off, MIDI or Key. In Key mode a clicked target binds the next plain key, captured
  before the shortcuts; conflicts are refused, Escape leaves the mode. The entry works without MIDI access
  (Safari). A `ControlSource` `"key"` tells key from MIDI at the parameter.
- **PR 3:** In Key mode the panel lists key mappings with Key, Track, Parameter, Min, Max and Key Mode. Preset
  version 2 adds `keyCode` and `keyMode`, version 1 still imports.
- **Later:** MIDI and key on the same parameter, a "Step" mode for stepped parameters, a key mapping warning in
  the shortcut editor.

## Design

- A key mapping is a `MIDIControllerBox` with the new string field `key-code` (12). Empty means a MIDI mapping,
  so existing projects keep their behaviour. The code is the layout-resolved code of the shortcut system
  (`Shortcut.resolveCode`, e.g. `KeyA`, `Digit1`).
- `MIDILearning` keeps one mapping per parameter. `createMapping` clears `key-code`, so learning MIDI on a key
  mapping turns it into a MIDI mapping, and `bindKey` turns any mapping into a key mapping.
- `accepts` rejects key mappings, so a CC never triggers one. `receiveKey(code, pressed)` delivers 127 or 0
  through the same `deliver` path as MIDI (min, max, frame coalescing).
- The int field `key-mode` (13) holds `MIDIKeyMode` (`Toggle = 0`, `Momentary = 1`). In toggle mode a press
  delivers 0 when the parameter (or its value pending for the next frame) is closer to max than to min,
  otherwise 127. `setKeyMode` changes it in one transaction.
- `bindKey` sets takeover to Jump and encoding to Absolute, so a former MIDI mapping with Pickup or a relative
  encoding does not swallow or misread the key values.
- `hasMidiConnection`, `controllerBoxes` and `numberOfConnections` only see MIDI mappings, so the MIDI mapping
  panel, its preset export, the map mode frames and the MIDI access prompt on load stay MIDI only without
  changes. `hasKeyConnection` and `forgetKeyConnection` cover keys. Preset import counts a replaced key mapping
  as replaced.
- `learnKey` listens for the next plain key (no Ctrl/Cmd, Shift or Alt) in the capture phase, so the key does
  not also trigger a shortcut. Escape cancels via the dialog. A key that a registered shortcut uses is refused
  with a message. It needs no MIDI access.
- `ComputerKeyControl` (app) forwards plain keys to the open project via `Surface.subscribeKeyboard` at default
  priority, after the `ShortcutManager`. A shortcut that consumes the key wins. Text fields and key repeat are
  ignored. Releases run at the highest priority so no other listener can swallow them, and every held key is
  released when the window loses focus.

## Known limits

- One mapping per parameter: a parameter is either MIDI or key mapped. The menu offers Forget for the mapped one.
- Shortcut conflicts are checked against the contexts registered when learning. A shortcut of a panel that is
  not open at that moment wins later while that panel has focus.
- The parameter's control-source indicator shows a key mapping as MIDI (PR 2).
